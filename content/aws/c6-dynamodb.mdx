DynamoDB is a database you never have to run: no servers to size, no disks to fill. It answers lookups in a few milliseconds at any size, as long as you look things up by **key**. That last part is what this lesson is about, because it changes how you design data.

## Tables, items, keys

- A **table** holds **items** (like rows).
- Items have **attributes** (like columns), but there's no fixed list of columns: each item can have different attributes.
- What every item *must* have is the table's **primary key**.

The primary key has one or two parts:

- The **partition key** decides which machine stores the item. DynamoDB spreads items across many machines by hashing this key (the idea from A5 and A10).
- An optional **sort key** orders items that share a partition key.

For orders, a good design is partition key `customer` and sort key `orderId`: all of one customer's orders live together, in order.

<Cmd>aws dynamodb create-table --table-name Orders --attribute-definitions AttributeName=customer,AttributeType=S AttributeName=orderId,AttributeType=S --key-schema AttributeName=customer,KeyType=HASH AttributeName=orderId,KeyType=RANGE --billing-mode PAY_PER_REQUEST</Cmd>

`HASH` means partition key and `RANGE` means sort key (old names, still used). You only define the key attributes; everything else is free-form. `PAY_PER_REQUEST` (on-demand) means you pay per read and write, with nothing to size up front.

New tables take a moment to create. `wait` pauses until it's ready:

<Cmd>aws dynamodb wait table-exists --table-name Orders</Cmd>

## Writing items

DynamoDB's JSON labels every value with its type: `{"S": "text"}` for a string, `{"N": "42"}` for a number (sent as a string, to keep precision).

<Cmd>{`aws dynamodb put-item --table-name Orders --item '{"customer":{"S":"asha"},"orderId":{"S":"2026-10-01"},"amount":{"N":"250"}}'`}</Cmd>

<Cmd>{`aws dynamodb put-item --table-name Orders --item '{"customer":{"S":"asha"},"orderId":{"S":"2026-10-12"},"amount":{"N":"900"}}'`}</Cmd>

<Cmd>{`aws dynamodb put-item --table-name Orders --item '{"customer":{"S":"ravi"},"orderId":{"S":"2026-10-03"},"amount":{"N":"120"}}'`}</Cmd>

## Query versus scan

**Query** finds items by key. It goes straight to one partition and reads only what matches:

<Cmd>{`aws dynamodb query --table-name Orders --key-condition-expression "customer = :c" --expression-attribute-values '{":c":{"S":"asha"}}'`}</Cmd>

`:c` is a placeholder whose value comes from `--expression-attribute-values`. Add `AND begins_with(orderId, :m)` to get one month, or `--no-scan-index-forward` for newest first.

**Scan** reads *every item in the table*, then filters:

<Cmd>{`aws dynamodb scan --table-name Orders --filter-expression "amount > :a" --expression-attribute-values '{":a":{"N":"200"}}'`}</Cmd>

Compare `Count` (items returned) with `ScannedCount` (items read). Here it's 2 versus 3. With a million orders it would be 2 versus a million, and you pay for every item read. So with DynamoDB, you decide your **access patterns** first ("get a customer's orders, newest first") and design keys to answer them with a query.

## Conditions: don't overwrite by accident

`put-item` replaces any item with the same key, silently. A **condition expression** makes the write happen only if something is true:

<Cmd>{`aws dynamodb put-item --table-name Orders --item '{"customer":{"S":"asha"},"orderId":{"S":"2026-10-01"}}' --condition-expression "attribute_not_exists(orderId)"`}</Cmd>

`ConditionalCheckFailedException`: the item exists, so nothing was overwritten. This is how you build "create only if new" safely, even with many writers at once.

## Counting without reading

To count page views, you might read the item, add one, and write it back. With two writers at once, one update gets lost (the lost update from A8). `update-item` with `ADD` changes the value inside the database, in one step:

<Cmd>{`aws dynamodb update-item --table-name Orders --key '{"customer":{"S":"asha"},"orderId":{"S":"2026-10-01"}}' --update-expression "ADD views :one" --expression-attribute-values '{":one":{"N":"1"}}' --return-values ALL_NEW`}</Cmd>

## Reserved words

DynamoDB reserves hundreds of words: `status`, `name`, `date`, `total`, `count`, `data`... Use one in an expression and you get "Attribute name is a reserved keyword". Give it a placeholder name starting with `#` instead:

```
--update-expression "SET #s = :s" --expression-attribute-names '{"#s":"status"}'
```

## What to remember

- Every item needs the primary key: a partition key, plus an optional sort key.
- Query reads one partition by key; scan reads the whole table. Design keys so your common lookups are queries.
- Condition expressions stop accidental overwrites; `ADD` updates counters safely.
- Values are typed (`S`, `N`), and reserved words need `#name` placeholders.
